# ブラウザ自動プレイ

固定シードの冒険を実ブラウザで進め、探索・戦闘・補給の判断と結果を記録します。ゲームの数値を変える前に、再現できる観測と比較条件を揃えるための土台です。

## 実行

Node.jsと[agent-browser](https://agent-browser.dev/commands)が必要です。ゲーム側に依存ライブラリを追加しません。

```sh
npm install --global agent-browser
agent-browser install
node check.cjs
node scripts/browser-playtest.cjs --seeds 101,102,103 --max-turns 600 --out output/playtest-baseline
```

ランナーが空いているポートで`dist/`をローカル配信し、専用のブラウザセッションを作成します。普段のブラウザのセーブや公開サイトには接続しません。終了時にセッションとHTTPサーバーを閉じます。出力先の再利用は拒否するため、比較時には別名を指定してください。

```sh
node scripts/browser-playtest.cjs --seeds 101,102,103 --max-turns 600 --out output/playtest-candidate
node scripts/browser-playtest.cjs --seeds 101 --viewport 320x568 --max-turns 100 --out output/playtest-small
node scripts/browser-playtest.cjs --seeds 101 --dungeon depths --max-turns 300 --out output/playtest-depths
```

- `--seeds`: カンマ区切りのuint32値。デフォルトは101,102,103です。
- `--max-turns`: 1冒険のターン上限。デフォルトは600です。
- `--max-actions`: 向き変更を含む判断回数の上限。デフォルトは1000です。
- `--delay`: 行動間隔の下限、単位ms。110〜5000、デフォルトは120です。さらに読み取り専用の`window.lanternGame.inputReady`で戦闘演出と95ms入力制限の終了を待ちます。フレームやゲームルールは高速化しません。
- `--viewport`: CSS px。デフォルトは390x844です。iPhone実機やタッチイベントの検証ではありません。
- `--dungeon depths`: 解放済みセーブから深淵を始めます。チュートリアルの実クリアや解放導線の検証にはなりません。

## 観測と操作の境界

初回だけ、同じエンジンで生成したセーブをブラウザに設定します。その後は製品のUIハンドラーだけで行動し、自動保存も通常どおり実行します。`window.lanternGame.snapshot()`は読み取りに使います。エンジンの移動・戦闘メソッドをブラウザから直接呼びません。

方策に渡す情報は、発見済み地形と階段、記憶された床アイテム、現在見える敵、発見済みの罠、自分の状態です。未識別の灯札は仮名に、未鑑定装備は種類だけに変換します。未発覚ミミックは金貨として扱い、未探索地形・見えない敵・隠れた罠・乱数状態を渡しません。完全なセーブは再現用の成果物にだけ保存します。

回復・食事・攻撃予告の回避・近接攻撃・矢の装備と照準・射撃・既知の強い装備・階段移動を優先し、その後に既知の道で補給と探索を進めます。未知装備の試着、鑑定対象の選択、持ち物交換、罠を踏んで進む判断は未実装です。方策の弱さが成績に含まれるため、到達階を人間の難易度に読み替えないでください。

主要ダイアログは実ブラウザのポインター入力で開閉し、閲覧による状態変化がないことを確認します。連続自動プレイはDOMの`click()`を使います。ポインターの当たり判定、押しやすさ、キーボードやタッチ操作全体の検証ではありません。

## 成果物と失敗の扱い

- `report.md`: 結果、評価の限界、次に確認する項目、詳細へのリンクです。
- `summary.json`: コミット、作業ツリー変更の有無、ソースのSHA-256、方策版、CLI版、実行条件、シード別集計です。
- `tutorial-101/actions.jsonl`など: 各操作、判断理由、行動前後のHP・満腹度・位置・既知アイテム数・見える敵、新しいログです。階を移ると発見済み情報のスナップショットも保存します。
- シード別ディレクトリ: 初期・終了・再読込後のセーブ、初期観測、実行結果、開始・階層遷移・終了・ダイアログ・失敗時の画像です。

画面サイズは起動後に設定し、再読込して縦画面用UIを初期化します。`innerWidth`・`innerHeight`・PNGの実寸も検証します。この準備では再開ログが2件追加されます。

検証用の再読込はゲーム状態全体を構造比較します。製品が追加する再開ログ1件だけを期待値に加え、HP・位置・乱数・所持品などは変更を許しません。ブラウザ例外、consoleのerror、保存復帰の不一致、横スクロール、入力停滞、ドライバー失敗は終了コード1になります。死亡や上限到達は観測結果として正常終了します。途中の失敗もシードごとの`run.json`に残ります。

## 改善点を見つける運用

1. 同じシード・方策版・画面サイズ・ターン上限で変更前後を比較します。方策を変えたときはゲーム変更と別の比較にします。コミットが同じでも作業ツリーを変更した場合は`sourceHashes`を確認します。
2. 最初に「どこへ進むか」「補給に寄るか」「敵と戦うか」の判断と結果を追います。再訪移動、低HPターン、空腹ターン、階層別到達ターンから気になる区間を絞り、`actions.jsonl`で原因を確認します。
3. 回復薬や装備の使い残し、罠回避による方策の停止を先に確認します。ボットの判断不足を、敵の弱体化や補給増加だけで解決しないようにします。
4. 固定シード群は回帰検証用に保持し、別のシード群で傾向を確認します。3シードの結果だけから、全体のクリア率やバランスを断定しません。
5. 満杯時の足元操作、鑑定と取消、呪い、モンスターハウス、死亡後の再挑戦、勝利と深淵解放は、状態を明示した専用ブラウザシナリオで補います。通常探索で偶然到達するのを待たず、探索成績とは別に集計します。
6. 最後に通常速度の人間プレイで、寄り道の期待、危険の予告、選択の納得感、魔物の見分け、演出の読みやすさを確認します。到達可能性と操作の再現性は自動化し、緊張感や満足度は人間が評価します。

`tests/check-playtest.cjs`は観測情報の隔離、回復・回避判断、角抜け防止、同じシードの操作再現性を検証します。`node check.cjs`に含まれます。ブラウザ実行自体はCLIとChromeが必要なため、別コマンドです。
